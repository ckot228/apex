# APEX DETAILING

Демонстрационный лендинг премиальной студии детейлинга. Самостоятельный статический проект на HTML/CSS/JavaScript, без npm-зависимостей, backend и внешних запросов при просмотре. Фотографии и Manrope хранятся локально.

## Как открыть

Самый простой способ — открыть `index.html` двойным щелчком. Для локального HTTP-просмотра нужен Node.js 20 или новее:

```powershell
cd "C:\Users\andre\Documents\ChatGPT\сайты\apex-detailing"
node server.mjs
```

Откройте `http://127.0.0.1:4185/apex-detailing/`. Остановка сервера — Ctrl+C. Сервер поддерживает корневой адрес и вложенный путь `/apex-detailing/`.

## Что реализовано

Все разделы из ТЗ, шесть услуг с демонстрационными ценами, переход к форме с выбранной услугой, мобильная навигация, галерея с модальным увеличением, стрелками и Escape, форма с проверкой полей и локальным подтверждением. Форма не отправляет и не сохраняет данные, после успешной проверки очищает поля. Без JavaScript отправка недоступна. Анимации учитывают reduced motion; содержимое доступно без JavaScript.

Фотографии иллюстративные, контакты и часы демонстрационные. Реальные работы, отзывы, статистика и достижения не выдумывались. Источники и лицензии — `credits.html`, лицензия шрифта — `assets/Manrope-OFL.txt`.

## Проверки и сборка

```powershell
node --check app.js
node verify.mjs
node build.mjs
```

Результат сборки — `dist/`. Установка пакетов не нужна. При наличии npm доступны равнозначные `npm run check` и `npm run build`.

`verify.mjs` проверяет существование файлов, якоря, уникальность ID, заголовок, ссылки услуг и галереи, отсутствие API передачи/хранения данных и граничные случаи валидации. Это не браузерный тест.

Браузерный доступ к локальному сайту был отклонён автоматическим контролем разрешений. Поэтому внешний вид, мобильная геометрия, консоль, клики, фокус и полный сценарий формы/галереи в живом браузере не подтверждены. Сайт не публиковался.

## GitHub Pages

В отдельный репозиторий, например `apex-detailing`, нужно поместить **содержимое этой папки**: `index.html`, `app.js`, стили, `assets/`, скрипты и `.github/`. Не загружайте родительскую папку с соседними сайтами. Локальная папка `dist/` не нужна в Git: её соберёт workflow.

1. Создайте свой репозиторий и загрузите исходники в ветку `main`.
2. В Settings → Pages → Build and deployment выберите Source: GitHub Actions.
3. Запустите workflow «Publish APEX to GitHub Pages» через Actions → Run workflow либо обновите `main` после настройки Pages.
4. После успешного запуска откройте адрес, который вернёт deployment. Для проектного репозитория он имеет вид `https://ВАШ-ЛОГИН.github.io/apex-detailing/`.

Workflow подготовлен по [официальной документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Его выполнение в GitHub пока не проверялось. Локально commit, push и публикация не выполнялись.

Альтернатива без Actions: загрузить **содержимое `dist/`** в корень отдельной publishing-ветки и выбрать эту ветку с `/ (root)` в настройках Pages. Не выбирайте `dist/` в интерфейсе Pages: для branch deployment он предлагает корень или `/docs`.

Все пути к стилям, шрифтам, изображениям и скриптам относительные. Специальная настройка base path не нужна, название репозитория можно менять.

## SEO перед публикацией

Title, description, Open Graph, язык, viewport, favicon, семантические заголовки и alt-тексты включены. Служебная страница лицензий имеет `noindex,follow`. Разметка реального LocalBusiness/Review не добавлена, поскольку бизнес и отзывы демонстрационные.

Workflow получает реальный URL из configure-pages и передаёт его в сборку. Сборка добавляет canonical, абсолютные OG URL/изображение и `sitemap.xml`. Для ручной сборки PowerShell:

```powershell
$env:SITE_URL = 'https://ВАШ-ЛОГИН.github.io/apex-detailing/'
node build.mjs
Remove-Item Env:SITE_URL
```

Замените пример настоящим URL. Без `SITE_URL` сборка не придумывает домен. На GitHub Pages в подкаталоге файл `/apex-detailing/robots.txt` не управляет обходом домена: robots при необходимости задаётся владельцем корня `ВАШ-ЛОГИН.github.io`. После публикации отдельно проверяются HTTPS, canonical, sitemap и реальные HTTP-статусы.
